# Практическая работа №1.3

**Тема:** фильтрация и сортировка связанных данных в Sequelize.

Проект на Node.js, Sequelize и SQLite. В нём пять запросов к связанным таблицам.

## Запуск

Нужен установленный Node.js.

```bash
npm install
npm start
```

При запуске создаётся `database.sqlite` и заполняется тестовыми данными. Таблицы пересоздаются при каждом запуске через `sync({ force: true })`.

## Задания

1. **User — Post:** пользователи с постами после 1 января 2023 года. Имена по возрастанию, посты по дате убывания.
2. **Author — Book:** все авторы, даже если у них нет книг. Сортировка по фамилии.
3. **Student — Course:** студенты с курсами, у которых больше 3 кредитов. Связь многие-ко-многим через Enrollment.
4. **Order — Item:** заказы с товарами в количестве больше 2. Заказы по дате убывания, товары по цене убывания.
5. **User — Post:** только активные пользователи с опубликованными постами.

Для запросов использованы `include`, `where`, `required` и `order`.

## Структура

- `database.js` — подключение к SQLite.
- `models/index.js` — все модели и их связи.
- `seed.js` — тестовые данные.
- `queries.js` — пять функций с запросами.
- `index.js` — запуск и вывод результатов.
- `.gitignore` — исключает базу данных и `node_modules`.

## Ответы на вопросы

**1. Почему `where` внутри `include`?** Потому что нужно проверить поле связанной таблицы, а не главной.

**2. Что будет без `required: true`?** Если внутри `include` есть `where`, Sequelize всё равно обычно включает `required: true` автоматически. Чтобы оставить всех родителей, нужно явно поставить `required: false`.

**3. Как сортировать на двух уровнях?** В `order` сначала указываем поле основной таблицы, затем поле связанной с указанием модели и `as`.

**4. Разница между `required: true` и `false`?** `true` использует `INNER JOIN`, `false` — `LEFT JOIN`.

**5. Как скрыть поля соединительной таблицы?** Указать `through: { attributes: [] }` внутри `include`.
